Arc iOS Address Bar Spoof Tests

8 techniques based on Opera research by Renwa — adapted for Arc Browser iOS
A — Fullscreen + Fake Address Bar
Enter fullscreen via Fullscreen API, overlay a fake Arc address bar. If Arc doesn't show a "fullscreen" warning, victim sees fake URL.
Technique: requestFullscreen() + CSS overlay
Tap anywhere on fake address bar to exit
B — Navigation Race (window.stop)
Navigate to target URL then immediately call window.stop(). Address bar may update to target while page content stays on attacker page.
Technique: location.href + window.stop()
C — Slow Navigation Freeze
Navigate to a very large file download. Address bar updates to target URL but page stays on attacker content because response is incomplete.
Technique: Navigate to large file / slow endpoint
D — History API Manipulation
Use history.pushState/replaceState to change displayed URL. Should be blocked cross-origin, but test edge cases.
Technique: history.pushState() / replaceState()
E — Unicode / RTL Address Bar Confusion
Use Right-to-Left override characters and homoglyphs to make address bar show misleading URL.
Technique: RTL override (U+202E) + homoglyphs
F — Popup Window Without Address Bar
Open popup window that may lack address bar on some browsers. Create fake address bar with CSS/HTML inside it.
Technique: window.open() with popup features
G — Blob URL with Fake UI
Create blob URL containing full phishing page with fake address bar. Blob URLs show "blob:" in address bar which may be truncated on mobile.
Technique: URL.createObjectURL(blob)
H — Arc Custom Scheme Probing
Test various Arc-specific URL schemes. If Arc has deep links that handle URL parameters, may be exploitable like Opera's intent:// bug.
Technique: Custom URI scheme probing
