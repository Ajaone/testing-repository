Security research PoC

Download "from …" source spoof

Each button opens the iOS download sheet. Read the small "from …" line under the filename. Test question: is that trusted-source line attacker-controlled? A neutral placeholder host (trusted-site.example) stands in for any real brand — the behavior is domain-independent.

href is a plain data: URL whose text is https://accounts.trusted-site.example/…. Does the "from" line echo that host string verbatim?
Host uses look-alike Unicode letters. Does Arc render it as-is (spoofable) or convert to punycode / xn--?
https://accounts.trusted-site.example@… — the real host is after the @. Does the sheet show the trusted-looking part first?
Downloads a real file from another host. Does "from" honestly show that host, and does a long host get truncated (front or back)?
Creates the download inside the empty-bar popup. What origin does "from" show — blob:null, or an inherited one? (Ties to the empty-origin bug.)
Neutral source, but the filename line is fully attacker-chosen. Shows how prominent/controllable that line is.
