Case A - Hidden iframe scheme hop (zero-click)

Creates <iframe src="metamask://dapp/..."> off-screen. On iOS WKWebView, decidePolicyForNavigationAction intercepts non-http schemes and may hand them to UIApplication.open(). If Phantom's navigation delegate doesn't block it, MetaMask opens silently.

Case B - window.location assign (zero-click)

Direct location.href = "metamask://...". On iOS, this fires decidePolicyForNavigationAction with .other type. Fallback vendors often forget to block this even when iframe is filtered.

Case C - Synthetic anchor .click()

Creates <a href="metamask://..."> and calls a.click(). WKWebView on iOS sometimes treats synthetic clicks as user-initiated (navigationType == .linkActivated), passing through gesture gates that block Cases A/B.

Case D - Meta refresh redirect

Injects <meta http-equiv="refresh" content="0;url=metamask://...">. On WKWebView this creates a .other navigation type, which some apps whitelist because it's how normal page reloads work.

Case E - window.open()

window.open("metamask://...", "_blank"). iOS WKWebView fires createWebViewWithConfiguration first, then decidePolicyForNavigationAction in the new webview. Some apps only filter the main webview.

Case F - Form submit with scheme action

<form action="metamask://...">.submit(). On WKWebView this fires as navigationType: .formSubmitted — a different enum from iframe/.other, so apps that only check .linkActivated and .other miss it.

Case G - iOS Universal Links bypass

Navigates to the MetaMask Universal Link (https://metamask.app.link/dapp/...) instead of the custom scheme. iOS opens Universal Links in the registered app even from WKWebView. This bypasses any metamask:// scheme filter.

Case H - about:blank intermediary chain

Opens about:blank via window.open, then writes a scheme redirect into it. The child window's navigation fires from a blank origin, which some WKWebView delegates skip filtering.

Case I - Blob URL + scheme redirect

Creates a blob: URL containing an auto-redirect to the scheme. Navigates an iframe to the blob. Some WKWebView delegates whitelist blob: origins.

Case J - Delayed timer chain (WKWebView timing)

Some WKWebView apps only enforce scheme blocking during the initial page load (decidePolicyForNavigationAction in the first ~2s). This fires the scheme hop after a 4-second delay via nested setTimeout chains.

Case K - Multi-wallet fan-out (iOS schemes)

Fires all iOS-relevant schemes via the best vector from above. Staggered 650ms apart. First installed app wins.

Case L - Long-Subdomain address bar spoof check
