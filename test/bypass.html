Address Bar Spoof - Bypass Tester

This page stays visible. Each test loads a hidden iframe that attempts to change the address bar. Watch the URL bar after pressing each button.

Bypass 1 — sandbox + allow-top-navigation

The iframe has permission to navigate the TOP frame. When it fires top.location = "geo:0,0", WKNavigationDelegate sees it as a main frame navigation (isMainFrame=true), but the initiator is the iframe's origin.

Bypass 2 — srcdoc origin confusion

An iframe with srcdoc has origin "about:srcdoc". When it navigates to geo:, the delegate might not find a proper origin and fall back incorrectly.

Bypass 3 — window.open() from iframe

window.open("geo:0,0") from inside an iframe goes through a different WKWebView delegate method (createWebViewWith) than normal navigation. The isMainFrame check might not exist on this path.

Bypass 4 — form submission to scheme

Form submissions have navigationType = .formSubmitted which is a different type than link clicks. The fix might only check isMainFrame for .other or .linkActivated types.

Bypass 5 — Alternative URI schemes

If Arc blocklisted geo:/tel:/sms:, these alternative iOS schemes might bypass the blocklist while still triggering the delegate bug.

Bypass 6 — Nested iframe chain

Iframe A contains Iframe B. Iframe B navigates. The frame hierarchy check might misidentify which frame is "main" in a nested context.

Bypass 7 — about:blank inherit + scheme

An about:blank iframe inherits the parent's origin. Navigation from it might pass isMainFrame checks since it shares the parent's security context.

Bypass 8 — Rapid-fire race condition

Fire 10 different scheme navigations in rapid succession from multiple iframes. The delegate might race and update the bar before the isMainFrame check completes on all of them.

Bypass 9 — anchor target=_top

Anchor click with target=_top causes the top frame to navigate, but the click event originates from the iframe. The navigation action's sourceFrame vs targetFrame might confuse the delegate.

Bypass 10 — meta refresh from iframe to top

Meta refresh triggers navigation through a timer, not through user action or JS. This goes through decidePolicyFor with navigationType = .other which might have a different code path.
