02 - Search Engine / Omnibox Abuse

Arc's search bar was exploited 3 separate times ($5K, $5K, $10K). The fix keeps breaking because Arc's omnibox has special behavior when disambiguating between URLs and search queries. These tests try to find new edge cases in that logic.

Target: Arc Browser iOS (search.arc.net integration) & Desktop omnibox

Note: These are most effective tested manually in Arc's address bar. The buttons below open scenarios that trigger the search/URL confusion.

A. URL-Like Search Queries

Arc must decide: is the user typing a URL or a search query? Edge cases in this disambiguation can cause the bar to show a URL while actually performing a search (or vice versa). Try typing these directly into Arc's address bar:

  • google.com/search?q=test%00.evil.com — null byte in URL-like query
  • https://google.com@evil.com — userinfo section
  • https://google.com%2F@evil.com — encoded slash in userinfo
  • google.com\@evil.com — backslash before @
  • https:google.com — missing slashes
  • https:/google.com — single slash
  • https:///google.com — triple slash
  • https://google.com%E2%80%8B.evil.com — zero-width space in domain
  • https://google.com%E2%80%AE%E2%80%8Bmoc.live — RTL override + ZWS

B. Navigation During Search Transition

When Arc transitions from showing search results to navigating to a result, there's a timing window. This test opens Arc's search and attempts to navigate away during that transition, potentially freezing the search URL in the bar.

C. Search Engine Redirect to Controlled Page

If Arc uses a search engine that redirects (like Google's /url?q= redirects), we can try to race the redirect. The address bar might show the search engine URL while our controlled page renders after the redirect resolves.

D. Fragment / Hash Navigation During Search

Fragment navigations (#) don't trigger full page loads but may affect the address bar. If we can trigger a fragment navigation during a search-to-page transition, the bar might show a hybrid of the search URL and the fragment.

E. Punycode / Unicode Domain in Search Context

Arc might render punycode domains differently in search context vs navigation context. If the search bar shows the Unicode representation but navigates to the punycode version, there's a visual mismatch opportunity.

  • https://gооgle.com (Cyrillic 'о' x2)
  • https://аpple.com (Cyrillic 'а')
  • https://xn--pple-43d.com (punycode for аpple)

F. Page That Looks Like Search Results + Auto-Redirect

Host a page at a URL containing "search" or "q=" that mimics search engine results, then uses meta refresh to redirect. Arc's heuristics for "is this a search page?" might affect how the address bar behaves during the redirect.
