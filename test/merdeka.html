CVE-2025-14812 Bypass Suite

MAIN-FRAME BYPASSES SUBFRAME FIX Arc iOS address bar spoofing — tests that evade the v1.45.2 patch
★ Class A — Main-Frame Pending-URL Strands
🟢 P1 — 204 No Content Strand
Navigate main frame to google.com/generate_204. HTTP 204 never commits a document → attacker page stays painted, bar shows google.com. Zero-click.
location.assign(google.com/generate_204) → didCommitNavigation never fires
🟠 P2 — Filtered Port Hang
Navigate to apple.com:8443 (firewall-dropped port). TCP SYN gets no reply → bar shows apple.com for ~30-75 seconds while attacker page stays. Spoofs ANY domain.
location.assign(apple.com:8443) → SYN timeout ~30-75s, no commit
🔵 P3 — Download Navigation Freeze
Navigate to a download URL (Content-Disposition: attachment). WKWebView converts to download, never commits. Bar stays on download host.
location.assign(github release .zip) → attachment policy-change, no commit
🔴 P4 — window.stop() Race
Navigate to chase.com, then window.stop() before commit. Bar updates to chase.com provisionally, stop cancels the load, attacker doc stays. Spoofs ANY domain.
location.assign(chase.com) → setTimeout(window.stop, 60) → no commit
🟣 P5 — window.open + 204 Strand
Open new tab to google.com/generate_204. 204 never commits → tab stays on writable about:blank. Write attacker doc via document.write(). Bar reads google.com over attacker content.
window.open(generate_204) → 204 no commit → opener document.write()
Class B — Alternative Trigger Paths
🧪 B1 — object/embed URI Scheme
Uses <object> and <embed> instead of <iframe> to trigger URI-scheme top navigation. WKWebView may not classify these as "subframes" in the same way.
<object type=text/html> + top.location = geo:0,0
🧪 B2 — Form Submit to URI Scheme
Hidden iframe auto-submits a form with target="_top" and action="geo:0,0". Form-driven navigation may be treated differently than script-driven top.location.
<form action="geo:0,0" target="_top">.submit()
🧪 B3 — Anchor Click URI Scheme
Hidden iframe auto-clicks an <a href="geo:0,0" target="_top">. Anchor-click navigation has different navigationType (.linkActivated) than script assignment.
<a href="geo:0,0" target="_top">.click()
🧪 B4 — Nested Frame + Different Schemes
Grandchild iframe (nested 2 deep) navigates top. Tests whether Arc's "subframe" check only checks immediate children, not grandchildren.
iframe → iframe → top.location = geo:0,0 (grandchild nav)
🧪 B5 — Same-Origin about:blank Frame
Creates an about:blank iframe (inherits parent origin). Writes script that navigates top to URI scheme. sourceFrame origin = parent origin → may confuse "is this a subframe?" check.
iframe(about:blank, same-origin) → top.location = geo:0,0
Class C — Exotic Schemes & Combos
🧪 C1 — Uncommon URI Scheme Probe
Tests URI schemes beyond geo:/tel:/sms: that may not be in Arc's denylist: maps:, comgooglemaps:, webcal:, x-apple-data-detectors:, shortcuts:, calshow:, facetime:.
iframe sandbox=allow-top-navigation + top.location = {scheme}
🧪 C2 — HTTP 302 → URI Scheme
Iframe navigates top to https://attacker.com/redir which 302-redirects to geo:0,0. Initial navigation is web-scheme (passes check?), redirect lands on URI scheme.
top.location = https://redir → 302 Location: geo:0,0
⚠️ Needs attacker server. Set up: res.redirect(302, 'geo:0,0')
