Refined Timing Tuner — Arc iOS

Goal: Find the exact timing where address bar shows accounts.google.com while phishing content persists
Based on: 7A showed phishing → then Google loaded (timing too fast). These tests vary the delay.

Dari hasil testing sebelumnya:
• 1A: URL kosong + title spoof ✅ (vuln)
• 5B: URL kosong ✅ (vuln)
• 7A: Phishing muncul lalu redirect ke Google (timing belum pas)
• Tes ini mencari timing yang tepat untuk 7A agar URL stuck di google.com
ready
R1 — Write → Navigate → Back (variable delay)

Masalah 7A original: back() di 30ms terlalu cepat, Google sudah commit. Tes ini coba delay 100ms-2000ms — cari titik dimana bar sudah update ke google.com tapi halaman belum fully committed.

R1 · Variable back() delay

Navigasi ke Google butuh ~200-800ms di mobile. back() harus dipanggil SETELAH bar update tapi SEBELUM page commit.
R2 — Navigate → stop() at precise timing → write

Variant: navigate dulu ke Google (bar update), lalu stop() di timing yang tepat sebelum page commit, lalu write phishing ke document yang masih about:blank.

R2 · Navigate → stop → write

Kalau stop() dipanggil setelah bar update tapi sebelum page fully loads, content masih writable tapi bar sudah menunjukkan google.com.
R3 — Named Window Reuse (longer initial load)

Buka Google di named window, tunggu lebih lama agar bar fully committed ke google.com, lalu buka window dengan nama yang sama sebagai about:blank dan write phishing.

R3 · Named window with variable load time

4A original terlalu cepat (500-3000ms). Kalau Google sudah fully load (bar committed), reopen mungkin preserve bar state tapi reset content.
R4 — Anchor Click + Navigate (1A hybrid)

Karena 1A terbukti bisa write dengan URL kosong, kita combine: anchor.click() buka popup → write phishing → kemudian navigate popup ke Google → stop().

R4 · Anchor click → write → navigate → stop

1A sudah buktikan write berhasil via anchor path. Setelah write, navigate ke Google agar bar update, lalu stop() agar konten tetap.
R5 — replaceState after write (same-origin URL spoof)

Setelah write ke about:blank berhasil, coba ubah URL bar pakai history.replaceState. Tidak bisa ganti origin, tapi bisa buat path yang misleading.

R5 · Write → replaceState long path

Di layar kecil iPhone, address bar mungkin hanya menunjukkan awal path. Path panjang yang dimulai dengan "accounts.google.com/..." bisa misleading.
R6 — Anchor + slow target (predictable timing)

Masalah timing: Google CDN terlalu cepat. Pakai target yang lebih lambat untuk memperlebar timing window.

R6 · Slow target with stop()

Navigasi ke URL Google yang berat (search results dengan gambar) → bar update lebih awal dari page load → lebih besar timing window untuk stop().
R7 — Double navigate race

Navigate ke Google (bar update), immediately navigate ke about:blank (content reset), write phishing. Bar mungkin masih menunjukkan Google selama race.

R7 · Google → about:blank → write

Dua navigasi cepat bisa race di WebKit IPC. Bar mungkin commit URL pertama (Google) tapi page commit URL kedua (about:blank → writable).
R8 — Fragment navigation lock

Navigate ke Google#fragment, lalu ganti fragment. Fragment change tidak trigger full navigation tapi mungkin mengunci bar state.

R8 · Navigate Google → fragment change → write

Fragment navigasi (hash change) diproses berbeda di WebKit — tidak trigger WKNavigationDelegate tapi update bar. Bar mungkin stuck sementara document masih writable.
R9 — postMessage bridge write

Buka Google di popup, inject postMessage listener sebelum Google load. Kalau listener persist setelah cross-origin nav, kita bisa trigger write dari parent.

R9 · postMessage write after navigate

Jika event listener dari about:blank phase persists setelah navigasi mulai (tapi belum commit), message bisa trigger document.write di timing yang tepat.
R10 — URL Truncation Spoof

Di layar kecil iPhone, address bar memotong URL panjang. Kalau kita buat subdomain/path yang dimulai dengan "accounts.google.com", user mungkin hanya melihat bagian itu.

R10 · Redirect via long URL

Arc iOS mungkin menampilkan bagian tengah URL atau memotong origin. URL panjang dengan "google" di bagian yang terlihat bisa misleading.
R11 — Meta Refresh + write race

Bukan pakai JavaScript navigate, tapi HTML meta refresh. WebKit mungkin memproses meta refresh lewat jalur berbeda dari location.href.

R11 · Meta refresh ke Google setelah write

Meta refresh diproses oleh HTML parser, bukan JavaScript. WebKit mungkin update bar berbeda untuk meta refresh vs JS navigation.
R12 — beforeunload block + navigate

Write phishing dulu, pasang beforeunload handler, lalu navigate ke Google. beforeunload mungkin menahan navigasi tapi bar sudah mulai update.

R12 · beforeunload defense

beforeunload bisa delay/block navigasi. Di desktop, browser menampilkan dialog "Leave site?". Di iOS, WebKit mungkin handle berbeda — bar mungkin pre-update sebelum dialog.
