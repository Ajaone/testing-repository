0 - Fingerprint

Detects Instagram WebView, WKWebView, iOS version, injected JS objects.

Category 1 — Address Bar Spoofing

1A - Long-Subdomain (BBRD: Safari $1k, Zerion, Coinbase)

Instagram's narrow bar shows ~30 chars of hostname. Navigate to apple.com.<padding>.attacker.tld — bar shows "apple.com…"

1B - URL-Freeze / Tab-Hanging (BBRD: Arc $10k, Safari CVE-2025-24128)

Load a URL on a non-responding port. Bar freezes on it. Then write phishing content via document.write or overlay. Bar still shows the frozen (trusted) URL.

1C - about:blank (BBRD: Safari $5k CVE-2025-24113, Google iOS $500)

window.open("about:blank") then doc.write(phishing). Bar may show blank/nothing or inherit parent origin.

1D - blob: URI (BBRD: Brave $250, Arc $500, Safari CVE-2025-24113)

Create blob:https://trusted.com/... with phishing HTML. Address bar may display the origin portion of the blob URL.

1E - history.pushState / replaceState

After page loads, call history.pushState(null,"","https://apple.com"). Some WebViews update the address bar without actually navigating.

1F - RTL Character Spoof (BBRD: Brave $250, Firefox $2k CVE-2024-11695)

Use Arabic/Hebrew chars in subdomains to reverse display direction in the address bar: ‮ (RLO) or RTL subdomains.

1G - data: URI (BBRD: Arc $1k, Brave iOS)

Navigate to data:text/html,<phishing>. Check what address bar shows.

1H - javascript: URI (BBRD: Firefox iOS $2.5k CVE-2025-23108)

Navigate to javascript:document.write(...) via anchor or location. If content replaces page but bar stays on original URL = spoof.

1I - Fullscreen API fake bar (BBRD: Arc $500, Opera $100)

Request fullscreen, hide real bar, draw CSS overlay that looks like Instagram's address bar showing a trusted domain.

1J - Meta-refresh timing race

Chain: navigate to https://apple.com but immediately <meta refresh> to attacker. If bar shows apple.com while content is attacker's = spoof.

1K - Invalid Scheme (BBRD: Arc $5k, Naver $200)

Navigate to made-up scheme like httpx://apple.com or malformed URLs. Parser confusion may display wrong hostname.

Category 2 — WebView Escape / Scheme Hop

2A - Custom scheme escape (same as Phantom PoC)

Fire mailto:, tel:, sms:, facetime:, shortcuts://, instagram:// via hidden iframe. If any opens an external app without prompt = escape bug.

2B - Universal Links escape

Navigate to Universal Links (e.g. https://metamask.app.link/...). If iOS opens the target app from inside IG WebView = escape.

2C - instagram:// deep link self-redirect

Use instagram:// scheme to navigate within the app itself. Can we trigger actions like DMs, profile views, or settings changes from a webpage?

Category 3 — Session / Data Leak

3A - Cookie / Storage enumeration

Read document.cookie, localStorage, sessionStorage. IG WebView may share session cookies with the app — session tokens exposed to any page loaded in-app.

3B - Injected JS objects / postMessage

Check for Instagram-injected JS bridge objects (window.IG*, webkit.messageHandlers.*). Also listen for any postMessage from IG native.

3C - Clipboard read / Geolocation / Camera

Test if IG WebView grants sensitive permissions automatically (clipboard, geolocation, camera/mic) without prompting.

Category 4 — UI Manipulation / Phishing

4A - CSS overlay fake Instagram login

Draw a pixel-perfect Instagram login dialog using only CSS, positioned over the WebView content. Captures credentials typed into the fake form.

4B - Scroll-based bar hide + fake bar

On iOS WKWebView, scrolling down often hides the address bar. Fill remaining space with a fake bar showing a trusted domain.

Evidence Monitor

Hooks visibilitychange, pagehide, blur, resize.
