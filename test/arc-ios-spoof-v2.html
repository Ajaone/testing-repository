Arc iOS Address Bar Spoof v2

iOS-specific techniques — no Fullscreen API or popup dependency
A1 — Video Fullscreen + Overlay
iOS only supports fullscreen on <video> elements. Enter video fullscreen, then overlay fake UI via CSS. When video goes fullscreen, DOM overlay may persist.
video.webkitEnterFullscreen() + CSS position:fixed overlay
A2 — Scroll-Away Address Bar Replacement
On iOS, scrolling down hides the real address bar. Create tall page that auto-scrolls, then position a fake address bar at the top. User sees fake bar instead of real one.
window.scrollTo() + position:fixed fake bar + 100vh spacer
B1 — Navigation + Immediate DOM Rewrite
Navigate to target, then immediately overwrite document. On some browsers the address bar updates before navigation completes and DOM write cancels navigation.
location.href = target; setTimeout(document.write, 0)
B2 — Meta Refresh Race
Inject meta refresh pointing to target URL with 0 delay, then immediately call window.stop(). Address bar may update while stop() prevents actual navigation.
meta http-equiv=refresh + window.stop()
B3 — Form POST + Slow Response
Submit a form via POST to target URL. Some browsers update address bar on form submit before response. If target is slow/unreachable, content stays.
form.action = target; form.submit() + unreachable target
B4 — setInterval Location Hammer
Rapidly alternate between target URL and current page using setInterval. May catch a frame where address bar shows target but content is attacker-controlled.
setInterval(location.href = target + window.stop(), 1)
C1 — about:blank Content Injection
Open about:blank or about:srcdoc, then document.write full phishing page. Check how Arc displays the URL for about: pages.
window.open("about:blank").document.write(phishing)
C2 — Data URL with Fake Authority
Open data URL using authority syntax: data://domain.com/,content. Some browsers display the authority in address bar (Opera Bug #1 variant).
data://accounts.google.com/,html_content
D1 — iframe Sandbox Navigation Race
Create sandboxed iframe with allow-top-navigation. iframe navigates top to target URL. Parent uses beforeunload/pagehide to write DOM before navigation completes.
iframe sandbox=allow-top-navigation + beforeunload DOM write
D2 — Full-page iframe Overlay
Create a full-screen iframe covering entire viewport including where address bar was. Combined with scroll-away technique to hide real bar.
iframe srcdoc with position:fixed covering viewport
E1 — JavaScript: URI Contexts
Test javascript: scheme in link clicks, form actions, meta refresh, iframe src. Check which contexts Arc allows execution and how address bar displays.
javascript: in href, formaction, meta refresh
F1 — Arc Universal Links Probe
Test Arc-specific deep links and universal links. Probe for URL parameters that Arc handles internally.
arc://, arc-search://, AASA check
F2 — PWA Display Standalone
Add-to-homescreen PWA with display:standalone hides browser UI. If Arc supports PWA install, full UI control is possible.
manifest.json display:standalone + theme-color
G1 — Pending Navigation + WebSocket Stall
Start navigation to target, keep connection alive via chunked transfer / SSE. Browser shows target URL but response never completes, attacker content persists.
EventSource to slow server + location change
