Zerion Wallet Browser — Spoof Tests

Open this page inside Zerion's dApp browser on iOS. Each test attempts to make the address bar show a different URL.

A: Failed Navigation Spoof

A1. location + window.stop()

Navigate to uniswap.org then immediately cancel with window.stop(). The wallet's onNavigationStateChange fires with the target URL, but content stays on this page. Address bar may show uniswap.org.

A2. Timing variations (10ms-500ms)

Same as A1 but with different delays before window.stop(). Tests various race windows between navigation start and cancellation.

A3. In new window + stop()

Opens about:blank, writes attacker content, then navigates to legitimate URL + stops. The new window's address bar may update.

A4. setInterval loop (AlphaWallet technique)

Continuously navigate + stop in a loop using setInterval. This was the exact technique that worked on AlphaWallet, MetaMask, Trust Wallet, and other top wallets.

A5. location.replace + stop()

Uses location.replace() instead of location.href assignment. replace() doesn't add history entry — might bypass history-based URL tracking.

B: History API

B1. pushState path spoofing

pushState can change the displayed path. If the wallet shows full URL (not just hostname), we can make the path look like a legitimate dApp. e.g., /app.uniswap.org/swap

B2. pushState + navigate race

pushState to a spoofed path, then immediately navigate to about:blank. During the transition, the address bar might flash the pushState URL.

B3. History flood + navigation

Push 200 history entries rapidly then navigate. The history stack overflow might confuse the wallet's URL tracking logic.

C: Window / Tab

C1. window.open + document.write

Open uniswap.org in new window, wait for URL bar update, then navigate to about:blank and write fake content. Address bar may keep showing uniswap.org.

C2. Named window replacement

Open uniswap.org with name 'w', then reopen about:blank with same name and write fake dApp. Named window reuse may preserve the original URL display.

C3. about:blank inherits opener origin

In some WebView implementations, about:blank inherits the opener's origin. If so, the address bar might show the parent page's URL.

C4. Blob URL

Create a blob: URL with fake dApp content. Wallet might show "blob:https://..." or nothing useful in the address bar, hiding the true origin.

D: iframe Spoofing

D1. Full-screen srcdoc iframe

Create a full-screen srcdoc iframe with fake dApp UI. Address bar shows THIS page's URL while content is completely attacker-controlled. User sees fake "Connect Wallet" on what appears to be a legitimate domain.

D2. sandbox + allow-top-navigation

iframe with sandbox="allow-scripts allow-top-navigation" tries to navigate the top frame. Worked on Arc iOS — might work on Zerion's WKWebView too.

D3. iframe bridge abuse

Child iframes in WKWebView can access window.webkit.messageHandlers without origin verification. Try to call the wallet's bridge from a cross-origin iframe.

E: Scheme Confusion

E1. data: URI

Navigate to data: URI with fake dApp page. Some wallet browsers show "data:" or nothing in address bar, hiding the attacker's control.

E2. javascript: URI

Try javascript: URI execution. If not blocked, we can modify the page content while the URL bar stays unchanged.

E3. ethereum: / wc: scheme

Test if ethereum: or wc: (WalletConnect) URIs cause address bar inconsistency during the app handoff.

F: UI Overlay

F1. CSS overlay fake address bar

Creates a position:fixed element at the top that mimics Zerion's address bar UI, showing "app.uniswap.org". The real address bar is scrolled away or hidden behind this overlay. Most reliable technique on mobile wallets.

F2. Scroll-away + fake bar

If Zerion hides the address bar on scroll (like many mobile browsers), scroll down to hide it, then show a CSS fake address bar in its place.

G: Combined Attacks

G1. stop() + overlay combo

Combines: (1) location+stop to set URL bar, (2) CSS overlay as fallback if stop() doesn't fully work. Double-layered spoofing for maximum reliability.

G2. Full attack simulation

Opens a new page with a complete fake Uniswap interface. Tries every spoofing technique in sequence. Tests the full attack chain a real attacker would use to steal wallet connections.
